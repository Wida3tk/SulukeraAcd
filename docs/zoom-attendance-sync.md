# Automatic Zoom attendance

Enabled October 18, 2026 for the three explicitly connected Zoom hosts using their separate secrets. Report-list, meeting-details and participant-report scopes were verified live for all three accounts. No new OAuth credentials are required. Graduation meeting `82789191279` remains excluded by explicit user instruction.

The existing every-minute Worker trigger now reserves every fifth invocation for attendance work, leaving the other four invocations to the existing grading/exam retry jobs. A report-discovery pass every ten minutes rotates hosts (each host approximately every thirty minutes); each pass fetches at most one previously unseen meeting from the preceding fourteen days. A meeting must have ended at least thirty minutes earlier. Full participant pagination, meeting-instance UUID encoding, meeting ID, timestamps and record count are verified before storage. The report snapshot stores names, email and join/leave timestamps only, not IP/device data. The existing report ready/retention limits of Zoom still apply; not all older meetings are guaranteed available.

`zoom_attendance_reports`, `zoom_attendance_state` and `zoom_attendance_aliases` are additive D1 tables. A database lease prevents concurrent work. One stored report is processed per attendance invocation. The private operations endpoint supports a read-only planning mode (default); applying must explicitly send `preview:false`. Automated jobs apply only safe matches. Errors/ambiguous targets move to review, not guessed grades. No student is marked absent merely for being missing or unidentifiable in a report.

Academic targets require date and meeting ID. Existing reviewed recording mappings override known historical rescheduling (e.g. Reem's October 14 lecture is lesson 1, not lesson 2). Shared cohorts are matched against their combined eligible roster, preventing duplicate names in different cohorts from being counted twice. Active account state, enrollment, course whitelist and QBA/QASP-S eligibility are enforced. Exact unique email, student number or full name are accepted; no fuzzy-name match is automatically approved. Reconnect/device overlaps are unioned and clipped to the real meeting interval. Grades use the existing policy (ABA 50/20/10 percent thresholds) through the attendance-only retry queue; basic-homework/reflection approval conditions remain unchanged.

Existing `course_attendance` records and manually entered grades, including explicit zero, are retained. There is an additional re-check immediately before the queued Firebase write to protect a manual correction made after matching. No homework/discussion/final-exam fields are synchronized by the attendance-only job. Professional session writes use conditional ETags, preserve watch progress and other session data, retain the existing 80-percent professional attendance policy and never overwrite an existing attendance percentage. Professional units with copied/ambiguous dates are held for review. Professional writes are bounded per pass to stay within Worker request limits.

Productivity uses the full report meeting interval, not recording length or the longest participant's attendance. The existing ledger format is reused. Matching ledger periods are checked before conditional insertion, including shared-cohort deduplication. It does not alter manually entered monthly productivity totals.

Administration → Lectures and assignments → “تقارير حضور Zoom والمزامنة” displays state, preserved/applied counts, unresolved names and target labels. Admin-only aliases are scoped to host and academic subject/professional track; the server revalidates active enrollment. Staff/guests can be explicitly excluded. Saving an alias requeues the report and carries the verified mapping into future lectures within that scope. Students and lecturers cannot read or mutate these reports. Reports requiring a lecture/date correction are shown as review items rather than silently mapped.

Initial live verification fetched reports from all three hosts. Most participant names were abbreviated, Latin transliterations or device labels; the first processed academic reports therefore retained manual attendance and queued the unidentified names for human confirmation. Do not describe this as all student attendance having been reconciled. The professional October 5 report correctly identified duplicate configured targets and was held for review. Existing grades were not zeroed. Unit tests cover exact/ambiguous identity, overlap clipping, copied professional dates, dry run, explicit-zero protection, attendance-only queueing and idempotence; the existing coursework suite tests a manual zero entered between matching and queue processing. Browser UI tests exercise report display, escaped names and alias submission.
