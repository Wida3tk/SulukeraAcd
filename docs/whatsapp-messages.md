# Manual WhatsApp messages

Full administrators can open **الطلاب → رسائل واتساب**, select recipients, exclude project students (on by default), restrict to active accounts (on by default), search by name/ID/phone and filter by batch. Individual checkboxes support named exclusions. Project exclusions combine the shared academic-stage policy with a read-only project roster request; the review is blocked if that roster cannot be verified. Existing administrative profile permissions are preserved; the new page does not widen the assistant or executive allowlists.

The message supports `{الاسم}` and `{الرقم_الطلابي}` placeholders. Review freezes the message and recipient queue. Editing text, country or selections invalidates that review. Numbers are normalized from Arabic/Persian digits, Saudi local mobile numbers and explicit international forms. Invalid numbers are disabled. Selected records sharing one normalized number create one queue item, with all associated names displayed before opening it.

Each explicit click opens one `web.whatsapp.com/send` link in a new tab, with the phone and text URL-encoded and `noopener noreferrer`. The administrator reviews the WhatsApp contact and presses Send there. No WhatsApp sessions, cookies, private APIs, browser automation, timers or bulk send requests are used. Returning to the system does not imply delivery. The separate confirmation button records only the administrator's declaration that they sent the message, and advances the queue. Opening the link and self-confirming a send have distinct activity entries; neither is a delivery receipt. The message body and phone are not copied into activity logs.

Composer state lives only in memory. Logout clears recipients, message, queue and project metadata. An auth identity change resets state, and asynchronous project responses are scoped to a session generation. Draft text and queues are not stored in browser storage or Firebase. Existing grade, attendance and assessment data is untouched.

Validation: `node scripts/whatsapp-messages.test.cjs`, `node scripts/whatsapp-messages-ui.test.cjs`, `node scripts/whatsapp-integration.test.cjs`. The browser fixtures use fictional students and intercept the WhatsApp test link; no actual messages are sent. Tests cover phone normalization, project and inactive exclusions, project API failure, named exclusions, duplicate numbers, Unicode escaping, preview invalidation, stale phone changes, manual confirmation, responsive layout, logout, full production HTML/navigation and administrative profile restrictions.
